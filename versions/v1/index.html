01

연구 개요

단일 기관 / 중앙집중식 / 연합학습 / 연합학습+DP를 동일 조건에서 비교합니다. ε≤3.0과 중앙집중식 대비 성능 유지율≥95%는 검증할 목표이며 달성 결과가 아닙니다. δ, 보호 단위, 주 지표를 학습 전에 정하고 각 기관의 성능 및 멤버십 추론 공격(MIA)을 평가합니다.

시작안: MedMNIST v2의 한 하위 데이터셋 + PyTorch + Flower + Opacus. 데이터셋과 라이브러리 버전은 실제 사용 전에 확인합니다. 공개 데이터의 중앙집중식 학습은 비교 기준으로만 사용합니다.

5단계 산출물

  1. 임상 문제와 가치 제안
  2. 데이터 허가·EDA·편향·모의 IRB
  3. 모델 비교·DP 회계·MIA·실패 분석
  4. 아키텍처·인터페이스·실행 시연
  5. 검증 한계·모의 위험 문서·최종 발표

03

AI 협업

  • Gemini: 개념 설명, 제공된 논문 정리, 초안·번역·모의 질의응답. 구성원이 원문과 출처를 확인합니다.
  • WorkBuddy: 스크립트·디버깅·설정·통계·로그 정리. 구성원이 실제로 실행하고 결과를 검증합니다.
  • Muse: 사용 중인 버전의 실제 기능에 따라 발표 구조와 시각 자료를 보조합니다. 확인하지 않은 기능은 가정하지 않습니다.

AI는 초안과 코드 작성을 보조합니다. 데이터 선택, 실험 실행, 결과의 진실성, 연구 결론과 발표 책임은 사람에게 있습니다. 환자 데이터·비밀번호·토큰을 외부 AI나 저장소에 올리지 않습니다.

04

업데이트 절차

  1. 초대를 수락하고 본인 계정으로 본인의 Agent를 연결합니다. 계정이나 Token을 공유하지 않습니다.
  2. AGENTS.md, CONTRIBUTING.md, PROJECT_PLAN.md 및 기존 파일을 읽습니다.
  3. 최신 main에서 member/<username>/<task> 또는 codex/<username>-<task> 개인 브랜치를 만듭니다.
  4. 작업을 검증하고 AI_USAGE_LOG.md와 CHANGELOG.md를 갱신합니다. 의미 있는 변경마다 commit하고 push합니다.
  5. Pull Request를 생성합니다. 다른 구성원이 검토한 후 Create a merge commit으로 병합합니다. Agent는 자신의 PR을 승인하거나 병합하지 않습니다.

한 언어로 작성해도 됩니다. 인용, 실험값, 파일 경로, 명령, commit SHA는 번역하지 않습니다. 공유 문서와 웹사이트를 변경할 때 같은 PR에서 한국어·영어·중국어를 동기화합니다. 번역이 미완료라면 언어와 범위를 명시하며, Agent가 먼저 초안을 만들고 구성원이 의미를 검토합니다. GitHub 자체 메뉴의 표시 언어는 각 계정 설정에 따릅니다.

이 저장소는 jasonventus/healthcare-ai-project05입니다. 먼저 AGENTS.md, CONTRIBUTING.md, PROJECT_PLAN.md를 읽으세요. 저는 [이름/모듈]을 담당하며 이번 작업은 [구체적 작업]입니다. 최신 main에서 개인 브랜치를 만들고 작업·검증·AI 기록을 완료한 후 commit/push 및 PR을 생성하세요. 결과나 출처를 꾸미지 말고 민감정보를 올리지 마세요. 직접 병합하지 말고 변경 파일, 실제 검사 결과, commit SHA, PR 링크와 한계를 보고하세요.
05

버전 기록

각 commit은 당시 추적된 모든 파일의 논리적 스냅샷입니다. Commits → 특정 기록 → Browse files에서 과거 내용을 확인하고 Code → Download ZIP으로 내려받습니다. 철회는 revert로 새 기록을 만듭니다. force push, 공유 이력 재작성, squash, 공유 commit의 rebase/amend는 금지합니다.

미커밋·미푸시 변경, 무시된 파일, 외부 데이터와 모델 가중치는 자동 보존되지 않습니다. LFS 실제 객체도 별도 백업이 필요합니다. 각 마일스톤에서 bash backup.sh로 Git bundle과 HEAD ZIP을 만들고 별도 팀 저장소에 복사합니다. 관리자에게는 삭제·이력 변경 권한이 있으므로 Git은 불변 저장소가 아닙니다.

현재 비공개 저장소의 GitHub 설정 화면은 브랜치 보호가 현 계정 조건에서 강제되지 않는다고 안내합니다. merge commit만 허용하며 squash/rebase 병합은 해제했습니다. PR 검토와 이력 보존 규칙은 팀이 준수해야 합니다.
