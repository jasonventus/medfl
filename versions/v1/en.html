01

Overview

Compare single-site, centralized, federated, and federated+DP models under comparable conditions. ε≤3.0 and ≥95% performance retention relative to the centralized baseline are targets to test, not achieved results. Define δ, the privacy unit and primary metric before training; evaluate each site and membership inference attacks (MIA).

Starting proposal: one MedMNIST v2 subset + PyTorch + Flower + Opacus. Confirm dataset access and library versions before use. Centralized training on public data is an experimental benchmark only.

Five delivery stages

  1. Clinical problem and value proposition
  2. Data permission, EDA, bias and mock IRB
  3. Model comparisons, DP accounting, MIA and failure analysis
  4. Architecture, interfaces and working demo
  5. Validation limits, mock risk documentation and final presentation

05

Version history

Each commit is a logical snapshot of all tracked files at that time. Open Commits → a record → Browse files to inspect a version, then Code → Download ZIP to export it. Undo through a new revert commit. Do not force-push, rewrite shared history, squash, or rebase/amend shared commits.

Uncommitted or unpushed edits, ignored files, external data and model weights are not automatically retained. Actual LFS objects need separate backup. At milestones run bash backup.sh to create a Git bundle and HEAD ZIP, then copy them to separate team storage. Owners can still delete or rewrite history; Git is not immutable storage.

The GitHub settings page currently says branch protection is not enforced for this private repository under the current account conditions. Merge commits remain enabled; squash and rebase merging are disabled. The team must follow the PR review and history-preservation rules.
