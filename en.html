04

Two-stage proposal

  • P1: ImageNet-pretrained EfficientNet-B0 or ResNet-18, 224×224 inputs. Freeze most weights and train the last block/LoRA and classifier using DP-SGD. Replace incompatible BatchNorm modules with compatible alternatives such as GroupNorm and validate with Opacus. Record any effect of converting pretrained components in the comparison.
  • P2: Clip each protected unit’s feature vector to R; release noisy per-class sums and counts to the server. Form noisy means and train a balanced classifier on equal numbers of virtual features per class. The virtual-feature distribution, dispersion and count remain to be specified; private estimates also need accounting.

Target final ε≤3.0, δ<1/n_i. The source’s (ε₁,ε₂)=(2.7,0.3) and ε₂∈{0.1,0.3,0.5,1.0} are search proposals. Adding ε labels or separately converting them is not a verified budget. Compose all rounds and statistics releases per client at common RDP orders, then convert once at the final δ and check the bound.

05

Privacy review conditions

  • Image-level DP is not automatically patient-level DP. Audit identifiers, repeated images and lesions; claim patient-level protection only with one record per patient, patient-level gradients or a justified group guarantee. Otherwise explicitly report image/record-level protection.
  • A parallel-composition argument requires disjoint patient ownership and conditionally DP site mechanisms covering the full interaction. Review the full transcript and cumulative per-site accounting; never reset the accountant between rounds.
  • Sums and counts form a joint release. For fixed encoding, single-label add/remove adjacency, one block has sum sensitivity≤R and count sensitivity≤1, but the joint vector/noise costs must be assessed together. A multilabel patient can affect several classes; the single-class argument cannot be reused unchanged.
  • Estimating the feature median R, class weights/counts, aggregation weights or adaptive clipping thresholds from private data may add privacy cost. Prefer public data or fixed rules.
  • Predefine floors/suppression for nonpositive or tiny noisy counts and empty classes. Postprocess DP outputs only; do not query true counts again. Report instability for rare classes.
  • Account for tuning, early stopping, repeated seeds, selection, intermediate checkpoints and released evaluations. Listing tuning runs does not restore privacy. ε=8/∞ runs are outside-target research references.

Basis: Kim eungyeul’s Chinese and English design v1.0, 2026-11-02. Korean is a translation/editorial synthesis in this update. RQs and methods are proposals; utility improvement and patient-level DP are not established facts. Added technical review conditions are separated in PRIVACY_REVIEW.md.

  • Report Balanced Accuracy, Macro-F1, DF/VASC recall and worst-class recall together. For Chest, report Hernia AUROC and AUPRC; select thresholds using validation only.
  • Per-class DP cost=non-DP score−DP score; report majority/rare cost gap, mean/minimum site performance and final ε/δ. If a test class lacks positives or negatives, report N/A and support rather than silently scoring zero.
  • C∈{0.1,0.5,1.0}, batch 128–512, 30–50 rounds and one local epoch per round are proposed search ranges. Plan ≥3 seeds and mean±SD. Freeze the run configuration after public-data exploration and resource checks.
  • Retain the course’s ≥95% centralized-relative utility target as a secondary criterion. Predefine its primary metric and use matched models, data and preprocessing. Overall accuracy alone cannot establish rare-class benefit.
