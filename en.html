Project 05 · Public skin-lesion images · Privacy-preserving training

When training protects privacy, are skin-lesion classes with few samples missed more often?

We simulate federated learning across six clients with public skin-lesion images, study how privacy protection affects minority-class* recognition, and compare ways to soften that effect.

Short answerYes. With privacy protection, recall for dermatofibroma and vascular lesions drops 64.2 points on average, while the common nevus drops 0.3. The best fix we tried, P2-LA, reaches 31.1% balanced accuracy, against 61.1% for non-private federated training.

Understand it in 3 minutesSee experiment progress

Member collaboration repository ↗Animated explainer

* Minority class: a class with a low share of images in the current training split; we look at dermatofibroma (DF) and vascular lesions (VASC). Not the same as a clinical rare disease.

Technical details: task, metrics, privacy unit
  • Task: 8-class skin-lesion classification on Fed-ISIC2019.
  • Metrics: per-class recall; balanced accuracy (mean recall over 8 classes); macro-F1 (mean F1 over 8 classes).
  • Privacy: image/sample-level differential privacy (DP-SGD training, RDP accounting) with a target cap of ε≤3 per model. Image-level protection is not automatically patient-level protection.
  • Scope: a federated simulation on public data with six source partitions.

03

Why run federated learning on public data?

Short answerWe use obtainable, reproducible public data to simulate data spread across separate parties, and compare collaborative training and privacy-protection methods.

Public datawhere the material comes from

Public datasets anyone can download and check; no hospital records.

Federated learningpartitions collaborate

Images stay in each partition; clients train locally and send only model parameters to a server that merges them. This is federated learning (FL).

Differential privacylimit what one record can change

Cap each image’s influence and add noise, so no one can tell whether an image was used. This is differential privacy (DP); a smaller budget ε means stronger protection.

Each partition keeps its own train and test set (18,597 / 4,650 in total, fixed split); no validation set is cut from ISIC. Equal-size nodes show structure only.

  1. The server sends the current model to six clients What travels is model parameters, never images.
  2. Each client trains locally: DP-SGD per-sample gradient clipping + noise At every training step, each image’s gradient contribution is capped, then Gaussian noise is added. The images never leave the client.
  3. Only the protected model update goes up Clients upload the parameters trained with DP-SGD, not images. After the first stage, P2 also uploads noisy class statistics once.
  4. The server averages the updates into the next model Updates are averaged by client size (FedAvg), sent back, and the round repeats. At the end, P2 builds balanced virtual features from the noisy statistics and retrains the head. The test set decides whether it helped.

Technical details: privacy settings
  • Federated averaging (FedAvg): the server averages model parameters weighted by client size.
  • DP-SGD: at every step each image’s gradient is clipped to a fixed norm and Gaussian noise is added; RDP accounting converts this to (ε, δ) at a fixed δ.
  • Protection unit: image/sample level for ISIC; patient level for the chest X-ray extension.
  • Budget: target cap ε≤3 per model; P2’s class-statistics release counts toward it. Actual cumulative ε differs between methods, so results list actual ε and δ separately.
  • ε covers a single model; the overall release across repeated runs and tuning is not composed.

Original: Original design: the last block or LoRA is DP fine-tuned together with the head. The block version was submitted in round 4 (P1-block); the LoRA version has not started.

P2 · Exchange protected class summaries, then retrain the head evenly

  1. Clip each record’s features
  2. Sum and count per class
  3. Add noise to the totals
  4. Release class summaries
  5. Build balanced virtual featuresnumber vectors, not images
  6. Retrain the head
Later fixes: P2-PCA and P2-LA

P2-PCA

Fit PCA on public auxiliary features (DermaMNIST), then run the six steps above in fewer dimensions. DermaMNIST images overlapping the ISIC test set were removed; the remaining images sit inside the ISIC training set.

Observation: classes move up and down.

P2-LA

No feature sums are released and the head is not retrained; DP class counts adjust the prediction scores (logit adjustment).

Observation: a limited improvement.

How far have we got, and what did we find?

Short answerAll 12 setups ran with 3 seeds. Among the 10 private setups the best balanced accuracy is P2-LA’s 31.1%, against 61.1% for non-private federated training and 73.9% for centralized training; the minority-class loss is not reliably recovered.

Animated explainer: the whole flow in 7 scenes

The whole flow as a metaphor: photos never leave their boxes, model copies study in parallel, noise is added while they learn, and only notes come back. The pictures are sketches with no experimental numbers.

  1. What is this? We teach a computer to tell 8 kinds of skin spots apart. Some spots have lots of photos (brown dots); some have very few (purple diamonds).
  2. Photos stay put The photos sit in 6 boxes (standing in for 6 sources). Not one photo is taken out.
  3. Robot copies study The teacher (server) copies the little robot (the model) six times, one per box, and all six study their photos at the same time.
  4. Fog while studying At every study step the robots sprinkle a little fog (noise), so nobody can tell whether one photo was used. This is differential privacy.
  5. Only notes travel The robots hand only their study notes (model parameters) to the teacher, who merges the six notes into one. The photos never leave the boxes. This is federated learning.
  6. Few photos fade first With the same fog, spots with few photos are forgotten more easily. We saw this in the experiments; the picture is a sketch.
  7. Looking for fixes We tried several ideas to help the robots remember rare spots. So far the gains are small, and teammates are still checking.
